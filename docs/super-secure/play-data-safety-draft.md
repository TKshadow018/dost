# Dost Play Data safety — owner draft

**Draft only; not a Play Console submission.** Reconcile each answer against the release APK, enabled build flags, Firebase configuration, provider contracts, and the live Play Console taxonomy before submission. This draft is for the planned 13+ app after the age-safety work ships; the current build still requires users to be 18 or older. Circle and Cipher are not implemented in this build; Shield and paid purchases are disabled by default.

## Audience and intended answers

- **Audience:** 13+, not under 13 and not Designed for Families. The age screen uses birth month/year for age-appropriate access. Do not retain or transmit an under-13 user's birth data or create an account for them. For 13+ users, the age cohort and minimum birth information used to apply age rules and advance a teen account at age 18 are account-linked until account deletion.
- **Collection:** Yes. Dost, Firebase/Google, and OpenRouter receive data described below when the corresponding feature is used. Local-only profile, chat, and settings data is not collected for Play purposes unless it is transmitted off-device.
- **Sharing:** Draft as sharing with service providers where required by Play's definitions: Firebase/Firestore and Authentication, Google Play/Play Developer API, Crashlytics, Dost's API host, OpenRouter, and the selected AI provider. Confirm each provider's contractual role and the exact answer in the current form.
- **Encryption in transit:** HTTPS/TLS is used for Dost API traffic and Firebase traffic. Verify every SDK and release configuration before selecting that all collected user data is encrypted in transit.
- **Deletion:** The app has an in-app control for indexed AI archives and profile deletion controls for People. Account deletion currently requires a request to `tushartk018@gmail.com`; confirm the account, Firestore, backups, logs, Crashlytics, and provider deletion process before declaring a complete deletion mechanism.
- **Contacts:** No address-book permission, upload, or address-book synchronization in v1. A contact connection created in the app is represented by user IDs, profile data, requests, and messages; do not report address-book contacts unless sync is later implemented.

## Cipher E2E classification rationale

Google Play's [Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469) says data sent off-device that is unreadable to the developer and anyone other than sender/recipient because of end-to-end encryption does not need to be disclosed. This is a conditional classification, not a blanket exemption for Cipher. Before launch, prove that encryption happens before upload, only chat participants possess the passphrase/key, Dost cannot access plaintext or recover the key, and backups/logs/notifications do not expose content. If any server or provider can read content, declare it as user-generated messages. Always separately declare metadata required for delivery (participants, timestamps, sizes, delivery tokens), and verify its categories, sharing, retention, and deletion path against the shipped implementation.
