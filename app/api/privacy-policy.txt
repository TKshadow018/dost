DOST PRIVACY POLICY
Effective date: November 17, 2026

ABOUT THIS POLICY
Dost is an Android app with AI companion chats and optional real-person profiles and messaging. This policy describes information stored on your device, information sent to Dost's API and AI providers, and optional People data stored in Firebase Firestore. AI companion chats and real-person chats use separate systems. You can export or import local AI-chat data and request deletion of this installation's indexed AI conversation archive from Settings.

1. INFORMATION STORED ON YOUR DEVICE
Dost stores the following information in the app's private storage on your Android device:
- Your profile information, including name, email, age, and gender.
- A random installation id created on the device.
- Friend profiles, selected friend photos, schedules, time zones, and relationship scores.
- Chat history, conversation summaries, and facts learned from conversations.
- Language, preferred AI model, anonymous analytics preference, unread counts, and other app settings.
- Compressed copies of photos that you attach to chat messages.
- A private draft of your optional People profile, including country, bio, and interests.

Chat transcripts are stored as per-friend files under the app's private messages directory. Memories, summaries, and settings are stored in the app's private preferences. The email in your local profile is stored on the device; Firebase Authentication separately processes your sign-in email/password or Google account identity. Settings can export your profile, friend profiles, memories, summaries, transcripts, and available chat-image attachments to a passphrase-encrypted JSON file, or import that file on a fresh install. The backup uses AES-256-GCM with a key derived from your passphrase using PBKDF2-HMAC-SHA256. The passphrase is not stored or sent to Dost; if you lose it, Dost cannot recover the backup. The export does not include your OpenRouter API key or installation id. Older unencrypted JSON exports remain importable; protect those files yourself. Friend-avatar references may point to files or URIs that are not available on another device.

Chat messages and chat-photo attachments are also sent to Dost's API server and AI services as described below. A friend photo selected as an avatar stays on the device. Choosing that photo does not upload it. A photo downloaded for a catalog friend is cached on the device.

Android backup and device-to-device transfer exclude the app preferences file (dost_local_data), the messages directory, the chat_images directory, and cached system-friend photos (system-friend-photos). Those files stay on the device; signing in does not sync or restore them. Use the encrypted export/import feature to move local data between devices.

2. INFORMATION SENT TO DOST AND AI SERVICES
When you request an AI response, Dost sends the following to Dost's API server for that turn:
- The message you just wrote and the earlier messages in the current session.
- The fictional friend's persona: name, age, gender, personality, interests, and the other profile fields the app uses so the character can stay in character.
- Up to six core facts from your saved people and preference profile, plus up to six additional saved facts selected for relevance to your latest message.
- Up to three relevant summaries from earlier sessions.
- Summaries of ended sessions, up to the seven most recent summaries.
- That friend's friendship score and love score.
- Your time zone and the friend's time zone.

This can include personal information you choose to share in the conversation, such as your name, preferences, relationships, interests, or other details in your messages. The age stored on your profile is sent as a `user_age` field with chat requests and can also be included if you stated it in a message or if the app saved it as a learned fact. Requests to generate a fictional friend profile send that friend's name, age, and gender.

The API server forwards AI prompts to OpenRouter, which routes them to the selected model provider. Chat requests and separately uploaded chat messages are archived on Dost's server for service operation and troubleshooting. The archive may contain user and AI messages, message timestamps and identifiers, the selected model ID, friend and user display names, the server-observed IP address used to organize the archive, chat-photo attachments, and, for lines written by the current server, the installation id. The archive is stored in folders named from the display name, that IP address, the friend name, and the session id. The server also keeps an index of those session folders for each installation id. Lines written before that index existed do not contain the installation id. API keys are not written into conversation logs.

A local keyword-and-phrase text heuristic checks chat text for romantic content when either supplied age is missing, invalid, or under 18, and checks for sexual text regardless of age. It can miss indirect wording and can flag benign text that matches an ambiguous term; it is not a guarantee of content moderation. It does not inspect image contents. Chat images are not forwarded when an age is under 18 or unusable; adult chat images are sent to the selected model provider without image-content moderation.

If you enable **Share anonymous event counts** in Settings, the app sends only an allowlisted event name when an action occurs: opening a friend profile, saving or forgetting a memory, retrying a failed send, starting a first message to a friend, saving a shared ritual, turning off or pausing friend-initiated messages, or completing an automatic friend reply. These requests do not include message content, profile details, account data, an installation id, or a client-supplied timestamp. Dost stores daily event totals for 90 days, without a user or device identifier. The API host may see your IP address as part of the network request. Turning the setting off stops future event requests; because the stored values are aggregate counts, individual past events cannot be removed.

If you choose to publish a People profile, the app stores your display name, broad age band, gender, country, optional bio and interests, contact preference, the adult age cohort, and visibility setting in Firebase Firestore. Your exact age, email address, and chat messages with people are not included in the public profile. Published profiles are discoverable to signed-in adult users. The profile age band is based on the age you enter at signup.

When you start a real-person chat, Firebase Firestore stores the conversation participants, limited profile snapshots, message text and timestamps, message identifiers, last-message previews, and per-participant unread counts. Opening a conversation clears that user's unread count. Both participants can read the conversation. These messages are not end-to-end encrypted, are not sent to Dost's AI API or OpenRouter, and are not included in the AI conversation archive. Firebase processes this data under Google's terms and privacy practices. Your contact preference determines whether other adult users can start a chat, must send a request, or cannot start a new chat. A request stores the sender and recipient identifiers, a limited sender-profile snapshot, its status and timestamps; the recipient can accept, ignore, block, or report it. Accepting a request also stores an approval record linking the two accounts to the conversation so Firestore can enforce the recipient's choice. A report stores the reporter and target account identifiers, a conversation or request reference, reason, and timestamp in Firestore. Only Firebase project administrators can review reports; we aim to review them within 72 hours. Reports are reviewed manually and do not automatically suspend an account or hide a profile. Reports are not an emergency service and may not be reviewed immediately; contact local emergency services if someone is in immediate danger. You may appeal an account or profile action by emailing the support address under Contact Us. Dost currently has no in-app deletion control for real-person messages, contact requests, contact approval records, or reports; hiding or deleting your profile does not erase existing conversation data or snapshots.

If you place or receive a People audio or video call, Firestore stores the participants, call type, status, offer/answer and network connection candidates needed to establish the call, and expiry timestamps. A private Firestore collection stores Firebase Cloud Messaging device tokens so Dost's Hostinger service can deliver incoming-call alerts; tokens are not visible to other users, and Firebase-reported invalid tokens are removed. The caller's display name is included in the incoming-call alert and may appear on your lock screen, depending on Android notification settings. Live audio and, for video calls, camera video are sent using WebRTC and are not recorded by Dost. Camera access is requested only for video calls. WebRTC encrypts media in transit; a configured TURN relay may forward encrypted media packets when a direct network connection is unavailable. Call signaling and account metadata are not end-to-end encrypted. Call and candidate documents are scheduled for deletion 55 minutes after call creation by Firestore TTL; deletion may be delayed by Firebase. Do not share sensitive information during a call.

OpenRouter and the selected model provider may process request data under their own privacy policies and terms. Dost does not control their independent retention or deletion practices. Please do not share passwords, API keys, authentication codes, financial-account credentials, or other highly sensitive information in conversations.

3. RETENTION AND DELETION
Removing a friend in the app deletes that friend's local data. The app removes the friend from the on-device friend list, reads image paths from the saved transcript, then deletes that friend's chat transcript file, referenced chat-photo files, learned memories, session summaries, unread count, current-session marker, and scheduled-reply flag. It also deletes the friend's app-private catalog photo copy, drops that friend's chat from memory, and cancels pending background work for that friend.

That deletion does not remove:
- The server conversation archive described below.
- Your profile (name, email, age, gender), installation id, language, model choice, or optional OpenRouter key.
- The original gallery photo you picked as an avatar. The app does not delete the gallery original.
- The shared system-friend catalog on the server. Removing a catalog friend deletes only your local copy of that character.
- Real-person chats or reports stored in Firebase Firestore.

Chat-photo files are stored in the app's chat_images directory. When you remove a friend, the app reads image paths from the saved transcript and removes the transcript and referenced chat-photo files. It also deletes that friend's cached catalog photo.

This version has no control that deletes your account or all local Dost data at once. Clearing Dost's app storage or uninstalling the app removes the local profile, friend list, transcripts, memories, settings, and other files the app stored in its private directories. Uninstalling does not delete data already sent to the server or Firebase.

You can hide or delete your People profile from the People screen. Hiding stops it appearing in discovery; deleting removes the profile document. Existing chat messages, profile snapshots in conversations, contact requests, contact approval records, block records, and submitted reports are not deleted by these actions. Social chat, contact-request, approval, and report records have no automatic retention period in this app; Firebase project administrators must manage their retention and deletion. Call and ICE-candidate signaling records have a 55-minute expiry and are removed asynchronously by Firestore TTL; device notification tokens remain until Firebase reports them invalid.

Dost server conversation archives are retained for no more than 1,095 days (three years) after the most recent activity in each conversation session. Activity is the last modification time of that session's archive file. A scheduled server cleanup removes expired session archives and their attached chat-photo files, including older archive files stored directly in the archive directory. The cleanup job does not run when you delete a friend, clear storage, or uninstall. The three-year limit is Dost's chosen retention period.

Optional anonymous daily event totals are retained for 90 days and then removed. They are separate from chat archives and are not associated with an installation id.

Use Settings > Delete server archive to ask the API to remove the conversation sessions and attached images indexed for the current installation id. A small hashed-installation deletion marker remains to prevent delayed messages created before deletion from being archived again; new messages can still be archived. This removes server records written by versions that stored and indexed that id; removing a friend, clearing app storage, or uninstalling does not make this request automatically. Archives written before install-id indexing existed cannot be associated with an installation by this control and remain subject to the 1,095-day cleanup. The app does not display the installation id, and server archives are not indexed by your Firebase account. If the delete request cannot reach the server, the archive remains until a later successful request or the scheduled cleanup.

Once data has been sent to OpenRouter or a model provider, their own deletion and retention policies apply.

The 1,095-day period applies to Dost's active server archive. Any infrastructure backup copies, if retained by a hosting provider, may follow a separate provider backup schedule. The cleanup job does not purge provider-managed backups.

4. OPENROUTER API KEY
If you provide your own OpenRouter API key, Dost stores it encrypted on your device using Android Keystore-backed encryption. When making a request, the app sends the key over HTTPS to Dost's API, which forwards it to OpenRouter and does not store it. You are responsible for protecting your key and any charges made through your OpenRouter account. If you leave the key blank, the API may use a server-configured key.

5. PHOTOS AND DEVICE PERMISSIONS
Dost uses Android's file picker when you choose a friend photo. The selected avatar URI is stored on your device and is not uploaded by the avatar feature. If you attach a photo to a chat message, Dost compresses it and sends it to the API server and AI provider as part of that request; a copy is kept in the server conversation archive until that archive expires or is removed.

The optional floating chat feature requires Android's draw-over-other-apps permission. Dost uses this permission to show the floating chat bubble and panel when you enable the feature.

People audio calls require microphone permission; video calls also require camera permission. Incoming-call alerts require Android notifications to be enabled; the app uses Firebase Cloud Messaging to show those alerts while it is in the background. You can revoke these permissions in Android settings. Dost does not continuously record from the microphone or camera, or store call audio or video.

6. DATA SHARING, ANALYTICS, AND ADVERTISING
Dost does not use advertising or third-party tracking services. Firebase Authentication processes your account identity for email/password or Google sign-in, email verification, and password reset. If you use People, Firebase Firestore additionally stores your published profile and contact preference, real-person chat messages, contact requests, accepted-contact approval records, blocks, reports, call signaling, and private call-notification tokens as described above. Anonymous usage analytics are optional and off by default. When enabled, Dost's API host receives only allowlisted event names and stores daily event totals for 90 days; it does not receive message content, profile details, account data, or installation ids for analytics. The host may see your IP address as part of normal HTTP requests. AI chat and profile-generation data is separately shared with Dost's API host, OpenRouter, and the model provider selected for the request.

7. AGE AND AUDIENCE
Dost is for adults because real-person matchmaking is a core app feature. Before initializing the app, Dost requests an age range from Google Play through the Play Age Signals API. Dost continues when the user or parent shares a range with a lower bound of 18 or older. If a range is not shared or Google Play cannot provide one, the app offers an explicit local self-attestation that the user is 18 or older; this is not independently verified. A minor range or a required-but-incomplete verification still blocks access. The API is beta, and Google Play notes that age-range sources may be based on information users provided and may not be independently confirmed in every region. Dost stores the self-attestation locally but does not store or send returned age-range values to its own servers. When the short-lived People eligibility claim is missing or nearly expired, the app sends a Firebase sign-in token and a Play Integrity token to Dost's API host. The host asks Google to verify the app, device, Play licensing, and integrity request, then sets a server-side eligibility claim on the Firebase account for up to six hours. The tokens are not stored by Dost; Google processes the Play Integrity token, and Firebase processes the eligibility claim. This check is tied to the genuine Play-distributed app but does not independently confirm the source of the age range. The signup form separately asks for a whole-number age from 18 through 120, which is not independent age verification. The Play Console Restrict Minor Access setting must also be enabled for the entire Play-distributed app. People profiles support adult age bands only.

Dost does not provide a child-directed service.
