01 · Overview

Dost is an Android conversation app built around a small collection of fictional AI friends. It combines a local-first profile and chat UI with an online PHP gateway that forwards AI requests to OpenRouter.

01 · Android UICompose screens collect profile settings, text, images, and friend choices.
02 · Conversation managerStores messages, checks busy windows, and schedules delayed work.
03 · PHP gatewayValidates requests, archives chat events, and calls the AI provider.
04 · OpenRouterRoutes the selected model and returns a character reply and structured data.

The app supports English, Bangla, and Hindi selection. The central product idea is that a user creates fictional companions, chats with them, and can configure their time zone and daily unavailable hours.

This document describes behavior found in the workspace source. A successful local build does not itself deploy the Android APK or the PHP service.

02 · Getting started

  1. The app opens to a splash screen and checks whether a local profile exists.
  2. First-time onboarding asks for the user's name, email, age, and gender.
  3. The next step can create the first friend using a name, age, gender, and optional photo, or skip adding a friend for now.
  4. After onboarding, the user lands on the friends list. The current implementation permits up to five friends.

This is profile onboarding, not a remote sign-in flow: the inspected Android code saves profile information in local app preferences and does not authenticate an account with a server.

When a friend is created, Dost first saves the basic friend record. It then asks the AI service to generate a fictional character profile, including personality, interests, family details, conversation style, and other profile fields. If that request fails, the basic friend remains available with its default profile values.

03 · Friends and profiles

Creating a friend

The add-friend form collects the friend's name, age, gender, photo, time zone, and daily busy schedule. The schedule controls include a Work or School choice, a start time, and a duration. The selected reason and schedule are stored on the friend record and the reason is included in the AI character context.

DefaultStartDurationResume buffer
School (age under 18)8:00 AM6 hours30 minutes after the busy interval

The user can customize the start hour and choose a duration from four to eight hours when creating a friend. The selected time zone determines the friend's local schedule. In the friend profile dialog, the time zone can be changed later; that dialog displays the busy interval but does not currently provide controls for editing the reason, start time, or duration.

Generated friend profile

The profile-generation prompt requests a fictional, internally consistent character and instructs the model not to use real private data. The generated fields are saved locally with the friend and later supplied as context for chat replies. The model can be selected in AI settings, so profile generation uses the currently preferred model too.

04 · Chat and reply flow

Sending a message

  1. The user's text or image is appended to the local conversation and saved before the AI request begins.
  2. The app checks whether the friend is inside their configured unavailable interval.
  3. If the friend is available, the recent session history and friend context are sent to the PHP API.
  4. The app parses the AI response, adds any explicit user facts to memory, updates relationship scores, and appends the assistant message.
  5. Message archival is also queued with Android WorkManager; network-dependent work waits for connectivity and can retry after transient failures.

The AI prompt includes the selected language, user and friend clocks, fictional friend profile, relationship scores, recent memory facts, and up to three recent session summaries. It tells the model to stay in character as a fictional friend, avoid claiming to be a real person, and return a JSON object containing the reply and optional structured updates.

Images

Images are resized to a maximum dimension of 1,280 pixels and compressed as JPEG to a maximum of 300 KB. The compressed copy is stored in the app's private files directory. The API forwards image data as a multimodal data URL; a vision-capable selected model is needed for useful image analysis.

Follow-ups and errors

The model is instructed to ask at most one question in a reply. If the user explicitly requests a future check-in duration, the structured response can specify a delay of one to 1,440 minutes. Otherwise, if a reply contains no question, the app schedules a default check-in after 30 seconds. If an AI request fails, the app now uses a distinct retry message instead of presenting the failure as a busy-hours reply.

05 · Busy schedule and delayed replies

Busy time is computed using the friend's time zone. The configured interval begins at the chosen start hour and lasts for the selected duration; replies become available 30 minutes after that interval ends. The calculation checks both the current local date and the previous date so schedules that cross midnight can be recognized.

When a message arrives during busy time

  1. The message is saved locally and the chat shows that a reply is waiting.
  2. A unique WorkManager job is scheduled for the calculated resume time.
  3. Additional messages can be added to the same waiting session.
  4. When the worker runs, it checks the schedule again and sends the latest session history if the friend is available.

WorkManager also requires network connectivity for AI and log jobs. A delayed reply can therefore occur later than the schedule boundary if the device is offline or background execution is deferred by Android. Updating a friend's time zone reschedules a pending busy reply.

The chat header shows either the current “busy until” time or the configured daily hours. The schedule uses the friend's clock, while the app separately stores a user time zone for displaying and prompting with the user's clock.

06 · Memory, relationship, and sessions

Personal memories

The AI is instructed to extract facts explicitly stated by the user, preserve who each fact is about, and avoid inventing details. Memories are stored by friend and are included in later prompts when relevant.

Relationship meters

The model returns bounded friendship and love impacts. The app clamps scores to 0–100. The love meter remains locked until friendship is above 70; if friendship falls to 70 or lower, love is reset to zero.

Conversation sessions

A session remains active while messages continue. Five minutes after the latest activity, the session-summary worker can summarize it, store the summary locally, and clear the current session ID. The next message then begins a new session. The chat menu exposes recent summaries, while up to three recent summaries are provided to the AI for continuity.

The app keeps message history locally for display. Session summaries and learned facts are also stored locally, separately per friend. The server archive is an additional copy; it is not the source used to render the chat UI.

07 · Floating chat

Dost can open a movable chat bubble over other apps. The user starts it from the chat menu using “Minimize chat.” Android requires the user to grant the draw-over-other-apps permission. The foreground service displays a notification while the overlay is active.

  • The bubble uses the selected friend's photo or an initial-based fallback avatar.
  • An unread badge is shown while the overlay is collapsed and messages are unread.
  • Tapping the bubble expands a compact chat panel; the bubble can be dragged and dismissed using the close target.
  • Opening the main Dost activity stops the overlay service.

The model catalog contains the free IDs listed by the PHP API as well as other OpenRouter IDs. Without a personal key, the API accepts only its server-side allowlist. With a personal key, the PHP API accepts syntactically valid provider/model IDs, and paid models may bill the user's OpenRouter account. The key is encrypted on-device with Android Keystore-backed AES-GCM and is not added to server conversation logs.

The settings screen also links to learned knowledge and supports deleting friends. Deleting a friend removes that friend from the local friend list; server archives have no automatic deletion or retention behavior in the inspected API.

09 · Data and privacy

Stored on the Android device

  • User profile fields, friends, schedules, time zones, scores, and selected model are stored in app preferences.
  • Conversation messages, session summaries, learned memories, unread counts, and message-log status are stored locally by friend.
  • Compressed chat images are stored under the app-private files/chat_images directory.
  • The optional OpenRouter API key is encrypted; other profile and conversation values are not encrypted by the app's own storage layer.

Sent to the service

Chat requests include message history and prompt context required to generate a reply. Profile generation sends the new friend's name, age, and gender. The PHP service saves chat events as JSON Lines, including text, timestamps, model IDs, and optional image filenames; chat images are stored alongside those logs. The API obtains the client IP from the web server and uses sanitized user and friend labels in archive paths.

Retention and access

The API README states that server logs have no automatic deletion or retention period and are not exposed through an HTTP read endpoint. Operators must protect the storage directory, define retention, and secure backups. The documented default is a log directory beside the API; a private directory outside the web root can be configured with DOST_CONVERSATION_STORAGE_DIR.

The Android manifest enables backup and references backup-rule files that currently contain only sample/commented rules. Review Android backup behavior and server retention settings before distributing the app with real personal data.

10 · AI backend

The Android client posts JSON to the PHP endpoint:

https://bisque-bear-900175.hostingersite.com/api/ai.php
Validate method and JSON› Rate-limit request› Validate model and messages› Archive chat history› Call OpenRouter› Archive assistant reply and return it
  • chat_reply includes installation, friend, and session IDs in request headers. The server validates identifiers, stores the supplied user/assistant history, calls OpenRouter, stores the returned assistant content, and returns the provider response.
  • log_message saves individual queued events. The server deduplicates events by message ID.
  • The default operation is a completion request used for generated profiles and summaries; it does not use the chat archive path.
  • AI requests are limited to 30 per client IP per minute and message-log requests to 120 per IP per minute.
  • The PHP host needs PHP with cURL and outbound HTTPS access. The server key is read from OPENROUTER_API_KEY or a server-only config.php.
  • The app uses connection/read timeouts; the PHP-to-provider request has a 10-second connect timeout and 90-second total timeout.

11 · Operations and troubleshooting

Known chat-reply deployment issue

Live status at last verification, 27 September 2026

A non-archiving completion POST to the live endpoint returned HTTP 200 and an AI response. A synthetic chat_reply POST returned HTTP 500. The workspace version of app/api/ai.php was corrected to pass all six archive-context values plus the event to append_conversation_event, and PHP syntax lint passed. Replaying against the hosted URL still returned HTTP 500, indicating the patched file had not yet been deployed or another hosted-side issue remains.

Deploy the workspace app/api/ai.php to the Hostinger API directory, then test an actual chat reply. A browser GET returning HTTP 405 with POST requests only confirms route reachability only; it does not verify the API key, provider request, or chat archival path.

Build and test

From the repository root on Windows, build the debug APK with:

.\gradlew.bat :app:assembleDebug

The APK is written to app/build/outputs/apk/debug/app-debug.apk. Run local Android unit tests with:

.\gradlew.bat :app:testDebugUnitTest

The app module uses application ID com.snigtus.dost, minimum Android API 26, target API 36, and compile API 37 in the checked-in Gradle configuration.
